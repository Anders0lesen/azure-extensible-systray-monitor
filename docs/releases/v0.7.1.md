# Azure Health Beacon 0.7.1

This security release removes Azure Health Beacon's dependency on the system Azure CLI.

## App-owned authorization

- Microsoft sign-in uses browser-based OAuth authorization code + PKCE.
- The reusable MSAL session is stored only in the Beacon's own Windows DPAPI CurrentUser-encrypted files.
- There is no plaintext-cache fallback, client secret, password field, Azure CLI subprocess, or access to `%USERPROFILE%\.azure`.
- Azure operations use direct HTTPS to fixed Microsoft Resource Manager, Resource Graph, Log Analytics/Application Insights, and Monitor endpoints.
- Tokens remain inside the private engine and never cross the WPF bridge, enter rules, logs, exports, or update traffic.

The hard 14-day boundary remains. Expiry and **Delete Azure connection** remove the encrypted identity cache while retaining rules.

The Settings page now uses the window horizontally: Windows/Monitoring and Azure/Updates sit in two compact columns, with short inline timing fields and compact action buttons.

## Upgrade behavior

v0.7.1 installs over v0.7.0 without another installer wizard. Existing rules, update choices, startup choices, and theme remain compatible. The legacy CLI authorization is deliberately deleted rather than imported, so one fresh Microsoft sign-in is required after the update.

The release workflow installs public v0.7.0, replaces it in place with v0.7.1, starts the new shell in a contaminated legacy PyInstaller environment, and verifies the installed version before publication.

This remains an unsigned public preview. Windows may show **Unknown publisher**; verify the published SHA-256 checksum and GitHub build-provenance attestation.
