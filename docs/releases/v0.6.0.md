# Azure Health Beacon v0.6.0

Download **AzureHealthBeacon-Setup-v0.6.0.exe** below and run it. Existing installations update silently in place after approval, then restart. This is a per-user Windows 11 installation and does not request administrator access.

## What changed

- **VM power state** is now a guided native rule. Choose a VM and decide which live `PowerState/...` values count as healthy.
- **Resource property (advanced)** can compare a selected ARM property using equality, exclusion, text, numeric, existence, or missing-value conditions.
- The old misleading **Resource property** label is now the honest **Provisioning state** label.
- Signal Explorer can pass a selected Azure resource directly into a native rule.
- Existing Resource Graph, Logs/Application Insights, and metric rules remain available for broader and custom signals.

## Update restart fix included

This release also includes the updater repair originally planned for 0.5.1. Both the app and installer reset inherited PyInstaller one-file state before restarting, which prevents the temporary `python312.dll` failure seen after earlier updates. The release pipeline now reproduces that stale runtime state and rejects the release if the restarted app does not stay running.

## Security notes

- Generic property paths use a constrained data-only format and are passed as one process argument; they are never evaluated by a local shell.
- Azure is asked to return only the selected property rather than the complete resource document.
- Rules still contain no credentials or tokens. Rule-pack schema 4 imports every rule disabled until it is reviewed, tested live, and explicitly enabled.
- Authentication still uses Microsoft's interactive flow and the Beacon-owned Azure CLI profile with its fixed 14-day deletion boundary.

The installer is not Authenticode-signed yet. Verify the accompanying SHA-256 checksum and GitHub artifact attestation before installation.
