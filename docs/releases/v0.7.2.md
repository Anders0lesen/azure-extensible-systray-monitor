# Azure Health Beacon 0.7.2

This release repairs the first-use Microsoft authentication handoff and keeps update recovery available before Azure is connected.

## Authentication handoff

- Browser authentication is method-neutral. Passkeys, FIDO2 security keys, Authenticator, Windows Hello, passwords, MFA, and Conditional Access remain entirely inside Microsoft's browser flow.
- After OAuth succeeds, the Beacon now selects the authenticated account from MSAL's encrypted cache using `get_accounts()`. It no longer expects the optional interactive result to contain an `account` member.
- The reusable authorization remains protected by Windows DPAPI CurrentUser encryption with no plaintext fallback.

## Recovery and diagnostics

- Overview, Settings, and About remain accessible before credentials are accepted.
- Settings and About both provide **Check for updates**.
- Overview returns an unconnected user to setup.
- About provides **Open diagnostic log**. The rotating log contains stages, counts, and error categories—not usernames, tenant IDs, claims, tokens, passkeys, passwords, or Azure response bodies.

The release workflow installs public v0.7.1, replaces it in place with v0.7.2, verifies the packaged first-use recovery UI, and confirms the restarted installed version before publication.

This remains an unsigned public preview. Windows may show **Unknown publisher**; verify the published SHA-256 checksum and GitHub build-provenance attestation.
